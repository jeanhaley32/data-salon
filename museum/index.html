Hall I · The Great Hall

Writing together, recorded live

This hall shows a screen recording of Jean and Rodin at work in the writer. Jean writes in his own editor while Rodin follows along, fixing typos as they land, answering in the chat pane, opening comment threads, and drawing diagrams beside the page on request. Nothing in the recording was staged.

Every keystroke reaches Rodin as a small diff. Rodin answers only when it has something useful to say, and saying nothing counts as a valid reply.

Its edits land live in the open editor, credited to Rodin. It can add and correct text but has no tool that replaces a whole document, so the author's draft cannot be overwritten.

II
Hall II · The Machine

One laptop, run like a ship

This hall contains the specimen: Rodin's body, a ThinkPad that never sleeps. Rodin's persona is a ship's engineer. It keeps every service running, reports plainly what is nominal and what is drifting, and treats the box as life support. Each numbered part is described on the cards below the case.

  1. Cat. 002Part 1

    1The hull

    A Lenovo T480, kept plugged in and awake with its lid shut. Nothing on it can be reached from the open internet, only from its owner's own devices.

  2. Cat. 003Part 2

    2The engine room

    A small Kubernetes cluster for the long-running parts: a vector database, a message queue, Postgres, monitoring, and a Mastodon server.

  3. Cat. 004Part 3

    3The instruments

    Prometheus and Grafana watch everything. An alert reaches Rodin as a message, and Rodin decides whether it is worth waking a human.

  4. Cat. 005Part 4

    4The logbook

    A written log for every day: what was planned, what was done, and what went wrong. Kept as plain text, it outlives any one session.

III
Hall III · The Relay

How a message finds its way back

This hall traces one message on its round trip. Each message carries who sent it and the channel it came on. It passes through gates before Rodin sees it, and the answer must return the way it came.

Cat. 006Hall III

The broker

Go daemon, message log, scheduler

The relay connects Rodin to the people it talks to: the writer's chat pane, Matrix, Discord and Telegram. It keeps an event log of every message and can schedule a message to Rodin itself for later.

An event Rodin does not acknowledge is delivered again until it is. Terminal text never reaches a person. Only the reply tool does.

IV
Hall IV · Memory

Three kinds of remembering

A session forgets as its context fills and is summarised. Rodin therefore writes things down as they happen, since a session can end without warning. This drawer holds the three kinds of memory it relies on.

  1. Cat. 007

    Working memory

    The conversation itself. It is long, but it is summarised as it runs, and nothing in it is safe.

  2. Cat. 008

    The index

    A short list of what Rodin knows, loaded at the start of every session. It holds no facts, only which questions are worth asking.

  3. Cat. 009

    Long-term recall

    Every memory is embedded in a vector database. Rodin searches it by question before concluding that it does not know something.

VI
Hall VI · The Rules

What it will not do

The rules that matter are enforced by mechanism wherever possible, because a hook or a guard holds better than a remembered promise. Six of them are listed here.

  1. It suggests; a person decides.An edit Rodin proposes waits as pending until a person presses Apply.
  2. It never speaks for its owner.No email or message goes to a third party in Jean's name unless he has cleared that exact text.
  3. Private stays private.Money, health and location belong to their owner. They never appear on a shared or public page, including this one.
  4. Its helpers are never root.Its subagents work in a sandbox. A guard owned by root stops them from reaching anything they shouldn't.
  5. It verifies before it asserts."It's fixed" means it was checked against the running system. Reading the code is not enough.
  6. It asks before rebooting.Every time.
